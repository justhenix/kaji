# Windows installer size audit

Measured on 7 November 2026, Windows x64, Bun 1.4.2. Both artifacts use the same NSIS LZMA solid compression and the same offline models.

| Artifact | Bytes | MiB |
| --- | ---: | ---: |
| Original target-highlights setup | 75,696,468 | 72.19 |
| Optimized setup | 70,468,636 | 67.20 |
| Reduction | **5,227,832** | **4.99 (6.91%)** |

Optimized SHA-256: `b6b3eb497b00aca1ea37f8b2d30c3acd6dcf1a9ce507c644905ee992bef68f93`.

The v0.1.2 release adds automatic device enrollment and the signed updater using Windows TLS: **70,716,901 bytes**, SHA-256 `923603b13c44b56acc752104cd72312376f52d16db371525491a5b81fab0100f`. This remains 4,979,567 bytes (6.58%) below the original setup. The updater's ZIP/archive and Rustls features are disabled because Windows uses the NSIS executable directly.

## Contents

These are exact extracted payload sizes from `7z l -slt`. NSIS uses one solid compressed stream, so per-file compressed contributions cannot be added independently.

| Component | Original bytes | Optimized bytes |
| --- | ---: | ---: |
| Compiled Bun agent, including its runtime | 87,238,656 | 86,602,240 |
| Rust GUI with embedded frontend/models | 42,003,456 | 29,823,488 |
| Isolated CPython, python-docx, lxml, licenses | 36,292,736 | 35,237,130 |
| Native UIA/action helpers, two executables | 2,216,960 | 1,224,192 |
| NSIS support files | 111,490 | 111,490 |
| Total extracted payload | **167,863,298** | **152,998,540** |

The original setup comprises 75,643,728 bytes of packed NSIS data, a 52,736-byte executable stub, and 4 framing bytes. The optimized packed data is 70,415,896 bytes with the same stub/framing.

The original Rust executable's `.rdata` section was 30,632,960 bytes and `.text` was 10,790,912 bytes. Its COFF symbol count was already zero; neither installer includes PDB files. Debug symbols were not the main cause of the download size.

Frontend build output falls from **73,513,476 to 58,375,709 bytes** before embedding/compression. The largest original files were:

| Asset | Bytes |
| --- | ---: |
| MediaPipe module WASM, unused by the chosen loader | 14,466,676 |
| MediaPipe classic SIMD WASM | 14,466,654 |
| Wake-word model data | 13,076,183 |
| MediaPipe classic non-SIMD WASM | 12,915,401 |
| Wake-word decoder WASM | 12,481,468 |
| Face landmark model | 3,758,596 |

`FilesetResolver.forVisionTasks(path)` in the pinned SDK defaults to the classic loader. The removed module pair accounts for 14,800,842 source bytes. Both classic SIMD and non-SIMD pairs remain, together with every voice/model asset. Existing builds already excluded frontend sourcemaps; the new build explicitly disables them and clears stale output first.

## Changes

- Release Rust uses `opt-level = "s"`, full LTO, one codegen unit, symbol stripping and `panic = "abort"`. Application errors continue to use `Result`; an unexpected panic terminates the process rather than unwinding.
- All app JavaScript bundles are minified. The compiled agent is minified with function/class names preserved for SDK compatibility. Its 86.6 MB runtime remains the largest payload component. Experimental Bun runtime trimming would require a toolchain migration; it is outside this build.
- Only the four MediaPipe loader files selected by the application are copied. Production output is rebuilt cleanly, so obsolete files cannot survive a rebuild.
- Python verification uses `-B`, removing 96 generated bytecode cache files from the setup. Python sources, standard library, SQLite support, DOCX/lxml dependencies, templates and licenses remain intact.
- Packaging resolves Python resources through `nativeTargetDir`, matching `CARGO_TARGET_DIR`. This fixes stale resources being copied from a different build directory.
- WebView2 already uses `downloadBootstrapper` with silent installation. The setup carries no fixed or offline Evergreen runtime; this setting is retained.

## Dependency review

Bundled `rusqlite`/SQLite is retained. Windows' active dependency graph has no `reqwest`; its lockfile entry serves other targets. Tokio is required by Tauri's async runtime. The duplicate-crate tree includes host/build and runtime graphs; it is not evidence that two full copies enter the GUI executable.

The selected Windows API features cover active native functionality. In particular, `Win32_Storage_Xps` supplies `PrintWindow` for capture, WinHTTP supplies the gateway transport, Cryptography supplies DPAPI, and UI Accessibility/COM/Jobs supply bounded native workers. These features are retained rather than removing called APIs for a smaller build graph.

## Verification

- `bun run --cwd app check` and all 69 app tests pass.
- All 94 release Rust unit tests pass, including on-disk SQLite history, retention and persistence tests.
- The real release Rust-to-Python DOCX create/edit test passes: `cargo test --locked --release --manifest-path app/src-tauri/Cargo.toml --lib rust_request_roundtrips -- --ignored`.
- `bun app/scripts/verify-assets.ts` initializes the actual packaged face model and runs inference using both default SIMD and explicit non-SIMD loaders in headless Chrome, without a camera or network fallback.
- `bun app/scripts/verify-overlay.ts` passes geometry, click-through, DPI, label-placement and clearing checks against the minified frontend.
- The minified compiled agent emits its real ready message and shuts down cleanly through JSONL.
- The setup installs silently; installed native binaries, agent and Python worker match the extracted installer payload hashes.
- A live Gemini 3.8 Flash Medium request through the installed composer resolves the real fixture button, supplies its exact Windows rectangle, renders the matching highlight, clears it on stop, and persists the request to SQLite. The test preserves foreground focus. Its future runner requires explicit `--execute` on an idle desktop because the composer and highlight are visible.
- Windows CI runs the real UIA/Guide and semantic-action fixtures against the release binaries. These tests execute on the hosted runner, not the developer's desktop.
- The public [download page](https://kaji.henix.my.id/download) automatically downloads 70,468,636 bytes without authentication. A clean headless browser independently hashes the complete download against the SHA-256 above, starts the manual retry, and verifies 1440/390/320 px layouts. `web/tests/download.ts` repeats this check using `EXPECTED_INSTALLER_SHA256` and `EXPECTED_INSTALLER_BYTES`.

Native overlay capture: [composer highlight](../verification/screenshots/composer-highlight-native.png). The composer verification runner's `--execute` flag is intentionally required; it must not be run while someone is working on the same desktop.

Live microphone and webcam capture were not exercised while the user was writing. The packaged model/decoder assets and native capture APIs remain available.

Build: `bun run --cwd app package:windows`. Resource paths support both the default and an explicit `CARGO_TARGET_DIR`.
